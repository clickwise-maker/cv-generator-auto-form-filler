## Repeat on another site

1. Inventory current routes/rendering/auth/exports/payments and actual feature/free limits. Record source/runtime evidence before advertising capabilities; absence of a quota is not unlimited usage.
2. Choose languages and target countries separately. Verify reachability, output scripts and legal obligations; a flag or translation is not availability.
3. Record exact source URLs/date/read scope/excerpts/hashes. Mark unread/blocked evidence unknown. Demand metrics need actual provider/country/date/window; null is not zero.
4. Cluster user intents into genuinely useful pages. Map to existing working product features. Do not create near-duplicate country/keyword doorway pages or unsupported AI/product claims.
5. Translate meaningful body/nav/FAQ/metadata, then obtain native review. Keep public-page language distinct from editor/OCR/export support.
6. Use request-local SSR data/context through hydration, not mutable server-global locale. Test mixed concurrent requests and RTL before release.
7. Design stable canonical URLs and preserved legacy links/auth state. One registry should generate self-canonical, reciprocal hreflang/x-default and sitemap only for real pages. Use proper BCP47 tags separately from URL IDs when needed.
8. Add factual graph/schema, social metadata, visible breadcrumbs and crawlable internal links. Match structured data to content; do not invent offers/ratings/contact details. Verify current search-feature eligibility. Keep search and training crawler policies separate and private exclusions effective in named groups.
9. Optional llms/project manifests are publishing conventions, not indexing/ranking requirements. IndexNow must remain disabled until an explicitly approved deployment/live ownership-key check and separate authorized submission; no automatic network side effects in builds/imports/tests.
10. Run source/JSON/XML/structural-schema tests, typecheck and safe builds. Verify raw HTTP statuses/body/head/language/canonical/alternates/sitemap and simultaneous locale isolation. Then test actual browser hydration,375/390px/mobile/desktop, keyboard/a11y/performance, auth and synthetic PDF/Unicode flows. A passing source suite is not launch readiness.
11. Review the exact diff/base and release artifact, preserve version/config backup, obtain deployment approval and use the supported uploader. Never bypass upload/network/security restrictions. Verify production before separately authorized webmaster actions; sitemap discovery is not indexing.
12. Monitor status/error rates and non-PII logs, crawler/sitemap processing and existing consented analytics. Event names may be proposed, never represented as already emitted. No guaranteed rankings, AI citations or income.
