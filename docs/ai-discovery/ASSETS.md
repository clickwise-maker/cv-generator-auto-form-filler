## Search versus training — deliberate build-time policy

`crawler-policy.json` has `trainingPolicy: "allow"` by default, preserving the existing public training-allow decision. A future reviewed source change can set `"deny"` and regenerate; there is no new runtime environment variable or production setting.

Every wildcard/named group carries the existing `/api/`, `/c/` and `/dashboard` crawl exclusions, avoiding the prior named-group precedence issue. This overlaps the robots intent in separate PR4, but PR4 has **not** been merged/cherry-picked. Robots are crawl preferences, not authentication or enforcement against arbitrary clients.

Only verified tokens in `platforms.json` are emitted. Public search permission for Googlebot/Bingbot and recorded search/user-fetch tokens is unchanged by the training toggle. Bingbot remains covered by wildcard policy rather than a newly guessed token record. `Bravebot` is not invented; the fetched official Brave documentation states no differentiated agent is advertised.

The deny option applies to **GPTBot, ClaudeBot, Google-Extended and Applebot-Extended**. It does **not** claim to block all AI training by unknown providers; they retain wildcard behavior. Google-Extended is a control token, not a separate HTTP crawler, and also affects some Gemini grounding. A training-deny setting can therefore affect those grounding uses; it does not control Google Search inclusion. User-requested fetchers can apply robots rules differently. Do not loosen security rules based on an agent name.
